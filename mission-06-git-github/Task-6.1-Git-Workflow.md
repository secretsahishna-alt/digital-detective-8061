# Task 6.1 — Understand the basic Git workflow

## Git Operations Table

| Git operation | What it does in your own words |
|---|---|
| **Check repository status** (`git status`) | Shows what is currently happening in the folder like which files are modified, untracked, or staged and ready to be committed. |
| **Stage selected changes** (`git add <file>`) | Moves files to staging area beforwe we commit. |
| **Create a commit** (`git commit -m "message"`) | Saves a permanent checkpoint/snapshot of the staged changes into the project's history with a small message description. |
| **View commit history** (`git log` / `git log --oneline`) | Displays the timeline of all previous commits, showing commit IDs, author names, timestamps, and commit messages. |

---

## Difference Between Staging and Committing

- **Staging (`git add`):** Choosing a file and keep it in s staging area so the github knows which file we have to commit.
- **Committing (`git commit`):** Creates a snapshot of work and changes done of the file that we have staged.
